Compose files for AI services differ from ordinary ones in three ways, and each
of the three is a production incident if it is copied from a web-app template.

**STARTER TEMPLATE — not a production deployment.**

```yaml path=docker-compose.yml
# Generated by StackForge.
# STARTER TEMPLATE - not a production deployment.
#
# Review before running:
#   - secrets are read from .env; nothing here is a credential
#   - volumes are named and local; point them at real storage
#   - health checks are conservative; tune to your model's load time
#   - resource limits are a starting point, not a measurement

services:
  vllm:
    image: vllm/vllm-openai:latest
    restart: unless-stopped
    command: --model ${VLLM_MODEL} --host 0.0.0.0 --gpu-memory-utilization 0.85
    ports:
      - "8000:8000"
    environment:
      HUGGING_FACE_HUB_TOKEN: ${HUGGING_FACE_HUB_TOKEN}
    volumes:
      - hf-cache:/root/.cache/huggingface
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 10s
      retries: 5
      # Weights take minutes to load. A default start_period restarts the
      # container forever, which looks like a crash loop and is an impatient
      # probe.
      start_period: 300s
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]

  qdrant:
    image: qdrant/qdrant:latest
    restart: unless-stopped
    ports:
      - "6333:6333"
    volumes:
      - qdrant-data:/qdrant/storage
    healthcheck:
      test: ["CMD-SHELL", "bash -c ':> /dev/tcp/127.0.0.1/6333'"]
      interval: 30s
      timeout: 10s
      retries: 5
      start_period: 20s

  redis:
    image: redis:7-alpine
    restart: unless-stopped
    # Without an eviction policy a full cache returns write errors on the
    # application path rather than evicting.
    command: redis-server --maxmemory 512mb --maxmemory-policy allkeys-lru
    volumes:
      - redis-data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 30s
      timeout: 10s
      retries: 5

  app:
    build: .
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      OPENAI_BASE_URL: http://vllm:8000/v1
      QDRANT_URL: http://qdrant:6333
      REDIS_URL: redis://redis:6379/0
    depends_on:
      # `service_healthy`, not a bare list. A dependency that has *started* is
      # not one that is ready, and a vector store still opening its index will
      # refuse the first writes.
      vllm:
        condition: service_healthy
      qdrant:
        condition: service_healthy
      redis:
        condition: service_healthy

volumes:
  hf-cache:
  qdrant-data:
  redis-data:
```

## The three differences

**Start periods are minutes, not seconds.** Loading weights is the slowest
thing in the file, and every default health-check timing assumes a process that
is ready in ten seconds.

**GPU reservations need the host toolkit.** Without the NVIDIA Container
Toolkit installed the container starts, silently runs on CPU, and you find out
from a latency graph rather than an error.

**Cache the model weights in a named volume.** Without `hf-cache`, every
container restart re-downloads several gigabytes — slow, and eventually
rate-limited.

## What to change before production

The resource limits, the memory ceiling on Redis, and the model. All three are
placeholders derived from a standard headroom factor rather than from a
measurement of your workload.
